# Decisions

One line per decision not fixed by the specs.

- 2026-11-13 Infrastructure is Terraform (`infra/`), not CDK, at the owner's request. Terraform outputs (`infra/outputs.json`) replace `cdk-outputs.json`; output names keep the spec's names (WebBucketName, DistributionId, WebUrl, UserPoolId, UserPoolClientId, CognitoDomain, ApiUrl).
- 2026-11-13 Specs and prototype moved from the repo root into `docs/` to match the spec's layout; repo root is `AutoMoto/` (the spec's `workshop-app/`).
- 2026-11-13 Backend TypeScript is one npm package (not multiple workspaces); each Lambda is bundled separately with esbuild into `backend/dist/<name>/index.mjs`.
- 2026-11-13 TypeScript pinned to 5.x (spec), zod 4, Node 20 runtime for Lambdas (local dev may use newer Node).
- 2026-11-13 Local Supabase: edge runtime, analytics and vector storage disabled in `config.toml` (unused).
- 2026-11-13 `verify_pin` reports PIN_INVALID via an HTTP 400 error response set with `response.status` (same `{code:"P0001", message:"PIN_INVALID"}` body as a raise) instead of `raise`, so the failed attempt row is committed and lockout works. PIN_LOCKED is a normal raise.
- 2026-11-13 Lockout window counts failures since the caller's last successful PIN (ordered by attempt id), max 5 in 5 minutes.
- 2026-11-13 `work_order_events` also carries `shop_id` so Realtime `postgres_changes` can filter `shop_id=eq.<shop>` on every published table.
- 2026-11-13 Job summaries include extra keys beyond the spec (vehicle_id, customer_id, concerns[], safety_note, completed_at, picked_up_at, odometer_km) for the arrivals cards; the documented keys are all present.
- 2026-11-13 Intake Lambda uses the official `@anthropic-ai/sdk` with structured outputs (`output_config.format`) plus the zod clamp. `temperature` is omitted (Claude Haiku 5.5 rejects non-default sampling parameters with a 400); `output_config.effort: "low"` keeps thinking short; `max_tokens` is 2000 (not 800) because thinking counts toward it.
- 2026-11-13 Intake rate limit (30 calls / 10 min per staff) is kept in a DynamoDB table with TTL (`RATE_LIMIT_TABLE`); without that env var (local/dev) it falls back to an in-memory per-container counter.
- 2026-11-13 Frontend styles are the prototype's global stylesheet (src/design/*.css, same class names) rather than CSS modules per component, so screens match the approved prototype exactly.
- 2026-11-13 "Order received by" in the job drawer is shown read-only with a "Set to me" button for front desk/admin: list_staff is admin-only, so front desk can't pick other staff.
- 2026-11-13 Drawers are URL-driven (?job=, ?vehicle=, ?customer=, ?tag=, ?staff=) and each one opened is a history entry, so Back works; the job tag is a drawer with a print stylesheet.
- 2026-11-13 Realtime: the client calls realtime.setAuth() before joining and every 5 minutes (otherwise it joins with the publishable key and RLS/private channels reject it); channels are created only after auth resolves (React StrictMode double-mount).
- 2026-11-13 Unsaved job edits are saved first when a status button is pressed, so a transition never discards them.
- 2026-11-13 Kiosk visit summary shows first name + "Phone ending NNNN" (the kiosk never receives full names or phones).
- 2026-11-13 "+ Start work order" in the vehicle drawer asks for the first concern (create_work_order requires one).
- 2026-11-13 e2e global setup resets the DB and waits until local Realtime delivers a change again (after db reset the local replication slot is rebuilt and early changes are dropped).
- 2026-11-14 Secrets are SSM Parameter Store SecureString parameters (standard tier, aws/ssm key) instead of Secrets Manager, to avoid US$0.40/secret/month; no rotation is needed (keys are rotated by hand). Terraform creates them with the placeholder "unset" and ignores later value changes; Lambdas get the parameter name in `<NAME>_PARAM` and treat the placeholder as missing.
- 2026-11-14 Supabase Free plan is acceptable for the demo (pauses after 7 idle days, no backups); Pro is required before real customer data.
- 2026-11-14 PIN fields show one slot per digit (4 required, 5th and 6th dashed as optional) over a transparent password input, so each key press is visibly registered; the input keeps the numeric keypad, paste and screen-reader support.
- 2026-11-14 Desk section tabs (and admin tabs) stay pinned below the top bar while scrolling; the current tab is shaded in the accent colour. On phones (≤ 640 px) the tall top bar scrolls away and only the tabs stay pinned.
- 2026-11-14 list_customers / list_vehicles take (p_query, p_limit, p_offset) and return { total, items } instead of a bare array (spec 8.4 had no search or paging). Customers match name, phone digits (3+) or a current plate; vehicles match plate, or VIN from 6 characters. Page size 25.
- 2026-11-14 Customer leaves without repairs: the front desk (not only admin, as in spec 8.3) can cancel a job from any open stage. A reason is required (job_transition p_reason, stored in work_orders.cancel_reason, shown in the drawer and in the "Cancelled by {name}. Reason: …" event). Work recorded so far stays on the job.
- 2026-11-14 seed.sql caps today's sample timestamps at now(), so pgTAP and e2e runs before 1 pm Toronto time no longer see events in the future.
- 2026-11-14 main takes width:100% (max 1240 px): #root is a flex column, so margin:auto alone shrank main to each tab's content and the tab bar width changed between tabs.
- 2026-11-14 One open work order per vehicle (partial unique index work_orders_one_open_per_vehicle; kiosk_check_in and create_work_order raise the new error VEHICLE_IN_SHOP with the open job's order number). Further concerns go on the open job. The kiosk greys out a vehicle that is in the shop (kiosk vehicle JSON gains `in_shop`; no history detail) and asks the customer to see the front desk; the vehicle drawer shows "Open job #…" instead of "+ Start work order".
- 2026-11-14 Seed: every demo vehicle had an open job (and the RAV4 had two), which left nothing to check in for spec scenarios 3, 5 and 6. Added Priya's 2020 Corolla (BTRL562, takes in-progress job e0007), Marco's 2017 Elantra (BKMR735, takes accepted job e0009), Daniel's 2022 Odyssey (BRVN204, free) and Mei's 2019 CX-5 (BNTR418, takes ready job e0010). The CR-V, Civic and Odyssey are free to check in.
- 2026-11-14 Customer visit history shows each visit's plate and year/make/model (a customer's visits span vehicles).
- 2026-11-14 Sign-in always sends `prompt=select_account` so Google shows its account chooser (staff switch on shared devices); this needs the Cognito domain on managed login v2 with default branding (`aws_cognito_managed_login_branding.web`).
- 2026-11-14 Demo data for the hosted project: `backend/supabase/demo-data.sql` (from seed.sql, attached to the existing shop, adds demo technician Sam Okonkwo PIN 1111), loaded/removed with `npm run demo:load` / `demo:remove` (psql; fixed demo UUID prefixes identify the rows).
- 2026-11-14 Customer texts (SMS): AWS End User Messaging SMS from a new `sms-api` Lambda (`POST /sms/send` on the existing HTTP API, JWT authorizer). The Lambda queues through `sms_queue` with the caller's token (all rules in Postgres), sends, then records the result in `sms_messages` with the secret key. Front desk/admin send; staff pick a template (ready, approval needed, waiting on parts, message) and may edit it. No origination number configured = status `simulated`.
- 2026-11-14 Text consent: `customers.sms_opt_in` (+ time, source). Kiosk check-in checkbox "Text me…" ticked by default (latest choice wins); desk can toggle in the customer drawer; a carrier opt-out (STOP) turns it off. No texts without consent (`SMS_NOT_ALLOWED`).
- 2026-11-14 "Customer approval needed" is a flag on the job (`approval_needed`, `approval_note`), set/cleared by workshop, desk or admin via `set_approval_needed` (bumps version, event kind `approval`); shown on cards and the job drawer. Shops gain an optional `phone` used in texts.
- 2026-11-20 Open source under the MIT licence. A repo-root package.json (no workspaces) gives newcomers `npm run setup` (scripts/setup.mjs: checks Node 20+ and Docker, runs npm ci in backend and frontend, creates frontend/public/config.json from config.example.json) and `npm run dev` (frontend dev:stack, which also creates config.json if it is missing). .nvmrc pins Node 20; *.tsbuildinfo is no longer tracked.
